## 📜 Overview

**The Dead Code Séance** is an AI-powered software archaeology tool designed to explore, understand, and revive abandoned, archived, or unfamiliar codebases.

Rather than treating legacy code as disposable, The Dead Code Séance reconstructs a project's development history from its Git commits, source code markers (`TODO`, `FIXME`, `HACK`), unresolved issues, and pull requests. Users interact with a conversational AI assistant that adopts the persona of the **Repository Ghost** — providing evidence-grounded answers about past architectural decisions, recurring bugs, and unfinished ambitions without hallucinating.

---

## 🔮 Key Capabilities

- **100% Local Inference & Privacy**: In local mode, source code and Git metadata never leave your computer. Queries are answered locally using open-weight **Gemma 2** models.
- **Strict Evidence Grounding**: Every claim made by the Repository Ghost cites verifiable surviving artifacts (e.g. `[Commit <hash>]`, `[File <path>:<line>]`, `[Issue #<number>]`). If records are inconclusive, the Ghost explicitly admits uncertainty.
- **Ghost Timeline**: Chronological interactive visualizer tracking major milestones, branch merges, and high-churn commits.
- **Unfinished Business Vault**: Scans source files and project documentation for abandoned branches, unfinished roadmap promises, and severity-ranked `TODO` / `FIXME` markers.
- **Resurrection Scroll**: Automated generation of comprehensive revival audits and step-by-step checklists, exportable to Markdown and JSON.

```
              └── Evidence Citation Validator
```

## 🚀 Quickstart Guide

### 1. Prerequisites
- **Git** (version 2.40+)
- **Python** (version 3.10+)
- **Node.js** (version 18+) & **npm**
- **Ollama** with Gemma installed:
  ```bash
  ollama run gemma2:2b
  ```

---

### 2. Backend Setup
1. Open a terminal in the project directory:
   ```bash
   cd backend
   pip install -r requirements.txt
   ```
2. Start the Flask API server:
   ```bash
   python app.py
   ```
   *The backend will initialize the SQLite database with FTS5 search tables at `backend/data/reposeance.db` and listen on `http://localhost:5000`.*

---

### 3. Frontend Setup
1. Open a second terminal:
   ```bash
   cd frontend
   npm install
   npm run dev
   ```
2. Open your browser at **`http://localhost:5173`**.

## 📡 REST API Reference

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/health` | Backend health & Ollama model connectivity check |
| `POST` | `/api/repositories/analyze` | Ingest local path or remote GitHub URL |
| `GET` | `/api/repositories` | List all tracked repositories |
| `GET` | `/api/repositories/{id}` | Detailed repository metadata & summary statistics |
| `GET` | `/api/repositories/{id}/timeline` | Chronological commit history with milestone filters |
| `GET` | `/api/repositories/{id}/unfinished`| Severity-ranked TODOs, FIXMEs, and open issues |
| `POST` | `/api/repositories/{id}/chat` | Ask the Repository Ghost an evidence-grounded question |
| `POST` | `/api/repositories/{id}/report` | Generate a structured Resurrection Report |
| `GET` | `/api/repositories/{id}/report` | Retrieve the latest generated Resurrection Report |

## 🛡 Privacy & Anti-Hallucination Guarantees

1. **Untrusted Code Ingestion**: Repositories are treated as untrusted data. No repository scripts or build commands are ever executed during ingestion.
2. **Citation Verification**: Every response generated by the local Gemma model is cross-referenced with surviving evidence stored in the SQLite index.
3. **No Cloud Leakage**: Repository contents and prompt context are never transmitted to external third-party inference services.
