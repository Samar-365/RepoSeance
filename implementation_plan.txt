# Implementation Plan: RepoSeance

An AI-powered software archaeology tool built for Hacktoberfest 2026: Ghost in the Machine. RepoSeance resurrects the context of abandoned, legacy, or unfamiliar Git repositories using local Gemma models, Git history extraction, and verifiable evidence grounding.

## 3. Database Schema (schema.sql)

Using SQLite with FTS5 (Full-Text Search) to ensure zero heavy external dependencies while delivering millisecond evidence retrieval:

1. repositories:
   id, name, source_type (local/remote), path_or_url, default_branch, total_commits, status (pending, analyzing, ready, failed), error_message, created_at, analyzed_at.
2. commits:
   id, repository_id, commit_hash, author_name, author_email, committed_at, message, files_changed_count, insertions, deletions, is_significant.
3. issues_prs:
   id, repository_id, type (issue/pr), number, title, body, state (open/closed/merged), author, created_at, closed_at, url.
4. unfinished_items:
   id, repository_id, category (todo, fixme, open_issue, abandoned_branch, dangling_doc), title, file_path, line_number, snippet, severity.
5. evidence_fts (Virtual FTS5 Table):
   Indexed fields for commits, file diff excerpts, documentation, and issue discussions to enable rapid context retrieval during chat.
6. reports:
   id, repository_id, report_type (resurrection_plan, full_audit), content_markdown, content_json, created_at.

## 5. Verification & Acceptance Criteria

1. Local Isolation: Ingestion and local chat must execute without sending repository code to any third-party remote API.
2. Citation Verifiability: At least 90% of factual assertions made by the AI chat must correlate with clickable evidence items stored in SQLite.
3. Graceful Fallbacks: If Ollama is not running, the application must display clear setup instructions rather than crashing, while continuing to serve the timeline, unfinished business scan, and metadata.
4. Export Readiness: User can download a structured Resurrection Plan with one click.
